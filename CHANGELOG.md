# Changelog

All notable changes to Azure Local Trailwright are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed
- **The Azure virtual network table asks for the address space** (`landing_zone.networks[].address_space`, a list of CIDR ranges, required by the toolkit's schema). A design that answers it exports a file the toolkit's `Test-InfrastructureFile.ps1`, `New-AzureLocalArmParameters.ps1` and the ZTP plan accept; before, every export with a virtual network failed the validator on the missing key.
- **The cluster Key Vault is not created again.** `cluster.key_vault.create_new` is `false` when the file references secrets in that vault (they exist before the deployment), instead of `true` for the vault that already holds them.
- **Thin or fixed provisioning is kept.** The volume model has `provisioning`, the Surveyor handoff 1.1 `provisioning_type` (and 1.0 `provisioning`) and the plan manifest fill it, the storage screen shows it and `storage.volumes[].provisioning_type` is written.
- **An import into a design that has data no longer wipes it.** The plan's sizing (cores, memory, drives) goes onto the machines by position; each machine keeps its name, address, serial number, BMC, management MAC, zone and storage addresses. The preview lists the drive layout, each volume (changed, added, removed) and the identity of a machine the plan removes.
- Hyperthreading, the default resiliency and the infrastructure volume of a Surveyor plan are in the import notes (the default resiliency also starts new volumes), and a plan has 1 to 16 machines (it was 1 to 64).

### Changed
- **`infrastructure.yml` describes the ports.** Every machine lists `nodes[].network_adapters[]` from the network cards (name, slot, port index, make, model, speed, RDMA, roles, `ip_assignment`), the management port carries the machine's address and MAC, and the file's `_metadata.scope` is `trailwright` (a planning scope: the MACs of the other ports are filled by hardware discovery). The management address mode can be a DHCP reservation (`dhcp_reservation`), and the deprecated `networking.management.ip_assignment` is no longer written. A machine without an address is an open question in the readiness list, not an invalid file.
- The vendored toolkit schema is 5.6.31. `npm run schema:sync --workspace apps/trailwright` copies it (and the Trailwright part of it) from the toolkit, sets `SCHEMA_VERSION` and regenerates the types; the schema test compares the copies with the toolkit's when `AZL_TOOLKIT_ROOT` is set, and CI checks the toolkit out and sets it, so the copy cannot drift.
- Questions for what the deployment needs from the provisioning step: `networking.management.provisioning_network` and `provisioning_dhcp_range`, `hardware.bmc.verify_certificate`, `hardware.sbe.family`, `publisher`, `manifest_source` and `manifest_creation_date`, and `deployment.events_directory`. `hardware.sbe.allow_unvalidated` is no longer asked (the schema says it is documentation only).
- The ARM and Bicep intents follow the toolkit's rule (`AzlArmDeployment.psm1`): `overrideAdapterProperty` is always true, and RDMA and jumbo frames are on only for storage traffic (an intent without storage gets RDMA off and 1514) unless the design overrides them.

### Deprecated
- **The environment file export** (`environment.yml`) is retired in favour of `infrastructure.yml`. It stays for one release with a deprecation notice in its header and in the export list, and is removed in the next release. The Terraform variables export is unchanged.

### Added
- **The schema 5 question catalog is on the screens.** Every screen shows, under its own fields, the `infrastructure.yml` questions the screens do not ask ("More for infrastructure.yml": 48 questions, for example the environment owner, site location and Azure tags, each machine's rack, rack position and Arc machine name, the GPU, the BMC login, the management IP assignment, time servers, the out-of-band network, the Active Directory NetBIOS name, domain controllers and groups, Entra groups, the deployment mode, the ISO source, the notification addresses, disaster recovery targets, Azure Hybrid Benefit, the network devices, and, when turned on, the Azure foundation and the CI/CD pipelines). The answers are saved in the project (`answers`) and written to `infrastructure.yml`. The catalog decides from the whole design what applies: a question that does not apply is not shown, its answer is not exported and it is not counted as missing (local identity drops the Active Directory answers, an ISO install drops the BMC login, CI/CD answers go out only when CI/CD is part of the design). What the screens answered always wins over a stored answer. A test checks that the screens' export never writes a key these questions own, so nothing is asked twice.
- **Review and export lists what `infrastructure.yml` still needs**, from the catalog over the whole design, grouped by who usually knows it (architect, datacenter, network, identity, Azure, security, operations), with how many of those hardware discovery can collect.
- **Import of the Surveyor sizing handoff** (`kind: azurelocal-sizing-handoff`, Surveyor's "Sizing handoff for Trailwright"): the machines, single rack or rack aware, cores and memory per machine, the drive layout and the volumes (in the schema 5 resiliency spelling) start the design; the sized capacity, utilization, workload totals and health check go into the notes. The test fixture is Surveyor's published example. Surveyor plan manifests and projects with a four-way mirror volume (Surveyor 2.9) no longer drop that volume.
- **`hardware.sbe.requirement` offers `vendor`** (schema 5.6.28) and new designs start with it, as the toolkit's schema and Trailwright template do: the automation's vendor catalog decides from `hardware.vendor` (required for Dell, HPE and DataON, whose package is a manual download; not required by default for Lenovo, whose cluster downloads it). The hardware screen and the handoff document say what that comes to for the design; SBE-001 warns when the catalog makes the package required and no location is given, and the new SBE-005 (information) asks the design to state the answer when the catalog cannot (an unlisted vendor, no vendor, or Lenovo). A saved project without the block opens as `vendor`.
- Project, hardware and provisioning questions that the schema 5 `infrastructure.yml` needs and no other answer gives: site name, site code and environment type (Project), vendor and model of the machines (Hardware and topology), and for simplified machine provisioning the provisioning image, the SMB share for the images with the management host address, and each machine's BMC address and management port MAC. All are optional in the design; a saved project without them still opens.
- Schema 5.1 questions: how each machine's management port gets its address before deployment (`networking.management.ip_assignment`: static, recommended, DHCP with a reservation, or already configured), and, with simplified provisioning, each machine's Arc machine name (`nodes[].arc_machine_name`, default the host name, checked against the Arc naming rule and for duplicates). The vendored schema, its generated types and the example fixtures follow the toolkit's 5.1 schema.
- Landing page: the app now opens on a page that says what Trailwright is and who it is for, how it works, the exports (listed from the export registry), where it fits between Surveyor and the build automation, the release it plans against (from `CURRENT_RELEASE`) and links to the documentation. From it you start a new design, open a saved project or a Surveyor plan, or explore the example; a design in progress gets a **Continue** link back to the step you last had open, and replacing it asks first and offers to save a copy.

### Fixed
- Volume sizes from a Surveyor plan or project are converted from decimal TB to GiB (rounded down). They were taken as binary TB, so every imported volume was about 10% larger than Surveyor planned (2 TB became 2048 GiB instead of 1862 GiB).

### Changed
- **The tool plans against Azure Local 12.2611** (12.2611.1004.9, released 2026-11-20), the newest generally available release: `CURRENT_RELEASE`, the Microsoft Learn `view=azloc-2611` links, the release lists of the rules (2611 added) and `docs/RULES.md`. Every rule was reviewed against the 2611 release notes, which change no design rule (new OS build 26100.33822, reliability fixes, .NET and PowerShell updates, simpler GPU management in the portal).
- The `infrastructure.yml` export follows the toolkit's schema 5.6.28 (`_metadata.schema_version: 5.6.28`, registry 5.0.62); the vendored schema, its types and the example fixture are synced. 5.6.28 adds only optional keys: the pipeline paths and tool versions (`devops.pipelines.infrastructure_file`, `handoff_path`, `tool_versions.*`), `devops.state.*`, `devops.runners[].*`, `devops.runner_network.*`, `devops.runner_access`, the Active Directory functional levels and DNS forwarders, the landing zone connectivity, virtual machine and policy keys, `key_vaults[].soft_delete_retention_days` and `allowed_ip_ranges`, the Defender for Cloud alert keys, `network_devices[].mtu`, `ports` and `ha`, and `azure.automation_identity.resource_group_roles[]`. The toolkit's Trailwright template lists none of them, so they are not written. It also adds the value `vendor` (now the default) to `hardware.sbe.requirement`; the export still writes the design's answer, `required` or `not_applicable`, which stay valid
- The `infrastructure.yml` export follows the toolkit's schema 5.6.27 (`_metadata.schema_version: 5.6.27`); the vendored schema, its types and the example fixture are synced. 5.6.27 added the optional Azure DevOps keys `devops.pipelines.service_connection` and `devops.pipelines.variable_group`, which the toolkit's Trailwright template does not list, so they are not written. The schema also drops the value `prompt` of `deployment.approval` (the export does not write that key) and now states the Network ATC defaults of the intent QoS overrides (7, 3, 50) and `roce_v2` for `network_direct_technology`, which are already the design's defaults
- The `infrastructure.yml` export follows the toolkit's schema 5.6.26 (`_metadata.schema_version: 5.6.26`); the vendored schema, its types and the example fixture are synced. 5.6.25 added the optional pipeline keys `devops.pipelines.runner_label` and `devops.pipelines.environments.*`, which the toolkit's Trailwright template does not list, so they are not written; 5.6.26 added no key and removed none that the export writes
- The `infrastructure.yml` export follows the toolkit's schema 5.6.24 (`_metadata.schema_version: 5.6.24`); the vendored schema, its types and the example fixture are synced. The export wrote none of the keys 5.6.20 removed (`landing_zone.resource_providers`, `landing_zone.log_analytics.resource_group` and `retention_days`, `identity.active_directory.service_accounts[]`, `identity.active_directory.join_options.rename_after_join`, `identity.entra.break_glass_accounts`, `provisioning.iso.image_version`), and a unit test now checks the export of every sample design for every key the toolkit removed and for any key the schema lacks. The question catalog no longer asks for `identity.active_directory.service_accounts`. The optional keys 5.6.17 to 5.6.24 added are not written: the toolkit's Trailwright template lists none of them and the design has no field for them (see `docs/INFRASTRUCTURE-YML.md`)
- The `infrastructure.yml` export follows the toolkit's schema 5.6.16 (`_metadata.schema_version: 5.6.16`); the vendored schema, its types and the example fixture are synced. Three keys the toolkit removed are no longer written: `operations.monitoring.health_alerts`, `security.backup_key_vault` and `sdn.default_access_policy`. The design still records those answers in the hand-off document
- **The `infrastructure.yml` export writes the Azure Local Toolkit's schema 5 layout** (`_metadata.schema_version: 5.6.10`) instead of the schema 4.0.0 layout. The sections are the schema's (`scenario`, `site`, `environment`, `azure`, `key_vaults`, `cluster`, `nodes`, `hardware`, `networking`, `identity`, `storage`, `security`, `sdn`, `operations`, `provisioning`, `disconnected`, `landing_zone`); `azure_platform`, `compute`, `infrastructure_network`, `connectivity` and `arm_parameters` are gone (the ARM parameters remain their own exports). A value the design does not hold is left out instead of being written empty, and a credential is written only when its Key Vault is known. `docs/INFRASTRUCTURE-YML.md` lists where each value goes, what has no key and which required keys the design cannot fill.
- The vendored toolkit schema (`src/infra/infrastructure.schema.json`) and its generated types are at 5.6.10, and the schema published at `/schema/infrastructure.schema.json` is now that same file instead of Trailwright's own 4.0.0 schema. The contract test validates the export of every sample design and of every choice a design can make against it.
- Azure Local family branding: the Azure Local Trailwright icon (SVG, favicon.ico, PNG 32, 180, 192 and 512, web manifest) is the favicon and the logo in the landing page header and the application sidebar, the page carries a description and Open Graph tags, the landing footer reads "Copyright © Hybrid Cloud Solutions & AzureLocal", and the README has the family banner and badges.
- The site address is now https://azurelocal.cloud/azurelocal-trailwright/ (the old labs.hybridsolutions.cloud address is gone); the published schema `$id` moves with it.
- The project steps sit behind the landing page: `/` is the landing page, each step keeps its own path (`#/project`, `#/storage` and so on), and an unknown path goes to the landing page. The sidebar title links back to the landing page.
- The management MAC question says it is the management port that provisioning targets, and reports a MAC used by two machines. The `use_dhcp` question now says it is the deployment's ARM `useDhcp`, not how the port gets its address.
- Integrated the pending dependency updates, including React 19 with matching DOM and type packages, Tailwind CSS 4 with its PostCSS plugin and explicit configuration, ESLint 10 with compatible hooks tooling, jsdom 30, Node type definitions and the pinned setup-node action.
- Updated the React element type annotation for React 19 and regenerated the npm lockfile after reconciling the dependency branches.

## [1.0.0] - 2026-10-15

First complete release. Plans against Azure Local 12.2609 (latest).

### Added
- Published JSON Schema (2020-12) for `infrastructure.yml` at `/schema/infrastructure.schema.json`, a field reference (`docs/INFRASTRUCTURE-YML.md`) and a contract test that fails the build when the exporter and the schema drift apart.
- Environment file (deploy automation) export: the cluster-facts subset of the deploy automation's `environment.yml`, with `CHANGE-ME` placeholders and TODO comments for what a design cannot know. Contract-tested against a vendored copy of that schema (`docs/ENVIRONMENT-FILE.md`).
- Terraform variables export (`terraform.tfvars.json`) for the deploy automation's cluster-deploy Terraform root.
- As-built compare: load an `as-built-snapshot.v1` file (for example from Azure Local Ranger) and see match, drift, missing and not-captured rows, with CSV and Markdown export (`docs/AS-BUILT.md`).
- Nested two-way mirror volumes for two-server clusters, including the Surveyor import mapping.
- Optional release build field; exports never guess the full build.
- Rules AZ-005 (deployment prefix, 1 to 8 characters), REL-001, and a stricter AZ-002 (machine name character set). `docs/RULES.md` is generated from the rule registry and a test keeps it current.
- Notes warning (do not type secrets) on the Project step and a notice in the project JSON export.
- LICENSE, CHANGELOG, CONTRIBUTING, AGENTS.md, repo-intent.md, Dependabot configuration and `npm run lint`.

### Changed
- Excel schedules are written by a small built-in writer (fflate) instead of the SheetJS `xlsx` package, which has known vulnerabilities and no fix on npm. Cell values are unchanged (golden-file test).
- Dependencies updated (jsPDF 4, jspdf-autotable 5, Vite, Vitest).
- Heavy libraries (PDF export) load on demand, which splits the large bundle chunk.
- The Playwright web server timeout is 180 seconds.
- `docs/REBUILD.md` replaced by `docs/HISTORY.md`.

### Removed
- The unused screen placeholder component.
